# Changelog

## 0.1.5

Fixes for the problems reported while using v0.1.3 with agents on a Windows host with WSL (WC-001 to WC-015), one settings file for every preference, agent instruction files in lanes, and per-agent selection. Version 0.1.4 was never released; its changes are included here.

- **Agent selection.** A lane serves the agent tools you choose instead of every tool's files: `WORKCOPY_AGENTS` (`auto`, `all`, or keys such as `kiro,codex,claude,gemini,opencode,cursor`), `create --agent TOOL`, the `agents` argument of `workcopy_create`, `workcopy_agent_context` and `workcopy_refresh_context`. With `auto` (the default) an MCP client's announced name decides (`claude-code`, `codex-mcp-client`, `gemini-cli-mcp-client`, `Roo Code`, `Kiro CLI` and others, matched by fragment); an unrecognised or absent client gets every tool. The choice is recorded in the lane so `sync` and refreshes stay consistent, `agent-context NAME --refresh --agent TOOL` moves a lane, and the report names the tools served, why, and known tools that have files but are not served. Catalogue split per tool (Claude, Gemini, Crush, Warp, Goose, Zed, Replit, Cline and Roo separately); the tool-neutral `AGENTS.md` family is always included. Lanes made earlier keep every tool.
- **Opt-in tool configuration.** The owner can copy specific tool configuration files, such as an MCP definition for their own tools, into every lane with `WORKCOPY_AGENT_CONTEXT_CONFIG`, and name exact files that may hold credentials with `WORKCOPY_AGENT_CONTEXT_SECRETS`. Both come only from the owner's settings, never from a repository or an MCP argument. Private keys, keystores and cloud or SSH credential stores are refused whatever is listed; a credential-looking file needs the exact-name opt-in and is marked `sensitive` in every report.
- **Clear refusals instead of raw errors.** Every way `create` can be refused for a reason the owner can fix now has a stable error code, an exit code of 2 or 3, a message that names the path and the way out, and happens before anything is written: no commits, a bare repository, a directory that is not a repository, Git's refusal of a repository owned by another account, an unknown branch, an unusable selection such as `.`, an unknown profile, tracked paths that cannot be written on every platform (reserved Windows names, `:`, `?`, `*`, `<`, `|`, trailing dots or spaces, `.git` and `.workcopy` components), submodules and oversize files (now told apart), unsafe symbolic links, and an account that cannot create symbolic links (Windows without Developer Mode). Lane names that Windows reserves (`con`, `nul`, `aux.txt`, `com1`) and trailing dots are now `invalid-name` up front instead of failing late with exit 5. [Table of codes](docs/troubleshooting.md#create-is-refused).
- **Windows: a symbolic link Workcopy just wrote no longer reads back as an edit.** Windows resolves a relative link target only with backslashes, so Go 1.27 (`os.Root.Symlink`, the toolchain this project pins) stores `bin/run.sh` as `bin\run.sh`; the lane then reported every tracked link as modified and would have committed it as a change. The target is now compared in Git's slash form. Absolute shared-dependency targets are compared exactly as before.
- **A lane whose creation cannot finish can be discarded.** Recover only retries, and every other command refused the lane, so a permanent failure stranded it until the registry was edited by hand. `destroy NAME --force` now removes the partial directory, the registration and the pinned ref of a lane stuck in `creating`, through the same quarantine and verified removal as an ordinary deletion. The creation error and the not-ready message say so.
- **Two tracked paths that the lane volume stores as one entry are refused up front.** macOS treats canonically equivalent Unicode spellings (`café` as one code point and as `e` plus an accent) as one file. Workcopy now asks the volume by replaying the non-ASCII layout in a scratch directory before anything is written, and refuses with `name-collision` quoting both spellings. It adds nothing on volumes that keep them apart.- **Review commits work where the identity comes from the environment.** `GIT_AUTHOR_*` and `GIT_COMMITTER_*` (name, email, date) are passed to Git; every other `GIT_*` variable is still removed. A missing identity is reported as `git-identity-missing` with the fix, before any object is written, and also by `--dry-run`.
- **Windows drives are recognised from the mount table.** The slowness and `prunable` warnings no longer depend on the drive being at `/mnt/c`: `[automount] root=/` layouts, WSL 1 `drvfs` mounts, extra mounts of a drive and custom mount points are detected from `/proc/self/mountinfo`, and a Linux filesystem mounted beneath a drive is not mistaken for it. A new page, [Windows, WSL and /mnt/c](docs/wsl.md), says which setup to use and what the slow one costs.- **`/mnt/c` performance, researched.** The slowness is the 9p round trip to Windows on every create, rename and close, which mount options do not change. Putting lane storage on the WSL filesystem (`WORKCOPY_ROOT`) while the repository stays on `/mnt/c` took a 1,000-file lane from 6.4 s to 0.46 s to create and 8.8 s to 0.75 s to review. `doctor` and `create` now say so. Creation also stops removing the temporary file it has just renamed and re-checking a path it has just examined. `go run ./tools/fsbench DIR` times the individual calls on any directory. See [validation](docs/validation.md#why-mntc-is-slow-researched).

- A lane whose directory was deleted outside Workcopy is listed with phase `missing`; `status` and `recover` report `workspace-missing`; `destroy` clears the registration and pins, keeps review worktrees and prints their `git worktree remove` commands (WC-015). Lane commands on a work root that does not exist yet now say the lane is not registered instead of leaking an operating-system error.
- Execute bits are tracked only when the repository allows it (`core.fileMode`) and the lane's filesystem stores them honestly. Lanes on WSL `/mnt/c` without metadata or on FAT no longer show every file as modified, and lanes created by v0.1.3 there heal on their next read (WC-001). This also removes the cause of "Review content changed" after a long `merge` (WC-004); `recover --abandon-review` releases a review that was interrupted and then edited, without deleting files.
- Lanes follow the repository's line endings: `.gitattributes` `text`/`eol`/`crlf`, `core.autocrlf` and `core.eol` decide each file's form exactly as `git checkout` would (verified byte for byte against Git across 2,720 cases). Comparison, hashing and three-way merge use the LF form, so a CRLF rewrite is neither a change nor a conflict; new files follow the same rules and commits stay LF (WC-005).
- `list` reports each lane's branch (WC-009).
- Lane creation, status, review preparation, cleanup and the preflight checks overlap file operations (`WORKCOPY_IO_WORKERS` to tune): about three times faster on Windows NTFS and WSL drvfs in single measurements (WC-003). Per-file `fsync` is retained.
- MCP: `--tool-timeout` sets the per-call deadline; clients that send a progress token receive file-count progress during creation and review; an expired deadline explains that `workcopy_recover` finishes the work (WC-011). Interrupted creation and review preparation have regression tests.
- `merge --json` omits the per-file inventory unless `--include-files` is given (WC-013).
- A path for the other operating system (`/mnt/c/...` to the Windows build, `C:\...` to Linux or macOS) is rejected with the path form to use (WC-012).
- `WORKCOPY_GIT` selects the Git program; `doctor` reports it, the line-ending and file-mode settings, and warns when the Linux build is used on a WSL Windows drive (WC-002, WC-006).
- Owner-supplied configuration may list `destroy.discard` patterns so build output does not need `--force`; a repository-committed configuration cannot grant this (WC-008).
- `destroy` run from inside the lane on WSL `/mnt/c` no longer fails after renaming the lane; the process now leaves the lane first on every platform.
- Documentation: default-profile versus `--project`, strict closure for ad-hoc projects and the lane-name rule inside a lane (WC-014); WSL, drvfs and `/mnt/c` guidance, validation evidence by filesystem (WC-010).
- CI adds Linux arm64 and macOS x86-64 runners and a FAT-volume job that reproduces the drvfs mode symptom. The per-package test timeout is ten minutes and the main job allows 40.
- One settings file (`workcopy.env`) holds every preference: lane location, owner configuration, MCP limits, deadline (now up to 24 h), shared-link allowlist, Git program, worker count, JSON default and the agent-context rules. Flag beats environment variable beats file beats default. `workcopy settings` shows each value and its source; `settings --init` writes a template. The MCP server reads the same file, so host definitions need no arguments.
- Lanes receive a private, lean copy of untracked agent instruction files (WC-007): a catalogue covering AGENTS.md, Kiro, Claude Code, Codex, Gemini, Antigravity, Cursor, Windsurf, Cline/Roo/Kilo, Continue, Copilot, Amazon Q, Junie, Augment, Trae, OpenHands and OpenCode, plus the owner's include and exclude lists. Credentials, tool settings, media, archives, history, caches, non-text files and symlinks are always refused, with the reason reported. Copies are excluded from status, reviews and commits, discarded by `destroy`, refreshed by `agent-context --refresh` and on `sync`. New `agent-context` command and `workcopy_agent_context` / `workcopy_refresh_context` tools; MCP bootstrap and the guide tell agents how to extend the list.
- Creating a lane writes each file straight from Git instead of staging a second copy, and review preparation avoids re-reading what it just verified: lane creation on NTFS is about nine times faster than v0.1.3 in the measurements in the validation page.
- Tests: a shared lifecycle run through the real binary for eleven repository and filesystem shapes (Unicode names, binary and unusual line-ending content, detached HEAD, shallow clone, linked worktree, sparse checkout, subdirectory start, ambient `GIT_DIR`, spaces and Unicode in the repository path, 1,200 files, paths beyond `MAX_PATH`, links and execute bits); every refusal above with its workaround; MCP parity for the refusals; both lane fixtures run natively on Linux with Node 22 and 24 and .NET 10 targeting `net8.0`. Each fix was confirmed by removing it and watching its test fail. A runner-parity run (a global `core.autocrlf=true` Git configuration, as on the Windows runners) reproduced the first CI failure exactly and now passes. Every command and MCP tool is required to be exercised (checked on each run); Windows Git versus Linux Git interop in both directions; concurrent processes; fuzz targets for the line-ending converter and the settings parser; settings isolation so a developer's own preferences never affect tests.
- CI: the full gate runs on Linux x86-64 and arm64, Windows, and macOS Apple silicon and x86-64; the .NET and Node lane fixtures run on both macOS architectures; a macOS-bash 3.2 wrapper check and an informational lifecycle timing step run on every platform.
