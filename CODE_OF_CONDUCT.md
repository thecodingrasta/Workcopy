# Code of Conduct

## Our Pledge

We want this project to be useful, welcoming and respectful for everyone.

Workcopy helps developers and AI agents work independently in selected source lanes from one Git repository, then prepares separate reviews for human-controlled integration.

Everyone participating in this project is expected to communicate with patience, respect and good faith.

## Expected Behaviour

Examples of positive behaviour include:

* being respectful of different experience levels,
* giving clear and constructive feedback,
* helping improve documentation,
* reporting bugs with useful details,
* disagreeing without being hostile,
* assuming good intent where reasonable,
* keeping discussions focused and productive,
* removing secrets from shared logs/configs,
* respecting maintainers’ time.

## Unacceptable Behaviour

Examples of unacceptable behaviour include:

* harassment, insults, threats, or personal attacks,
* discriminatory language or behaviour,
* trolling or deliberately derailing discussions,
* repeated low-effort demands,
* posting someone else’s private information,
* sharing credentials, tokens, private keys, or secrets,
* pressuring maintainers for unpaid support,
* abusive comments about users, contributors, maintainers, or communities involved in the project,
* knowingly submitting malicious code or instructions.

## Support Expectations

This is an open-source project maintained in spare time.

Please remember:

* bug reports should include reproduction details,
* setup questions belong in Discussions where possible,
* maintainers may close vague or inactive issues,
* feature requests may be declined if they do not fit the project scope,
* respectful disagreement is fine,
* entitlement is not.

## Project Scope

This project focuses on:

* creating selected, Git-free development lanes from committed repository snapshots for parallel developer and agent work,
* discovering projects, reconciling changes and resolving conflicts while preserving the original checkout's HEAD, index and user edits,
* preparing separate Git reviews for human inspection and integration,
* providing a CLI, local MCP server, and storage-aware guidance for safe, cross-platform use.

Discussions that are unrelated to the project will be closed.

## Enforcement

Project maintainers may take action when behaviour harms the project or community.

Actions may include:

1. asking the person to stop,
2. editing or removing comments,
3. closing or locking issues/discussions,
4. blocking users from the repository,
5. reporting abuse to GitHub.

The goal is not to over-police normal disagreement. The goal is to keep the project useful, safe and respectful.

## Reporting Problems

If you see behaviour that violates this Code of Conduct, please contact the project maintainer privately where possible.

Do not use public issues to escalate interpersonal disputes unless there is no reasonable alternative.

For security issues, use `SECURITY.md` instead.
